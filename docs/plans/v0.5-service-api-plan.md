## 3. Scope decisions

D1 - **Optional extra, lazy imports.** The service lives behind a
`service` extra. `import vlm_engineering` must keep working without
FastAPI/pydantic installed. `service/schemas.py` imports `pydantic`, which
is not a base dependency, so `service/__init__.py` wraps its imports in a
guarded import that raises a helpful
`ImportError("... pip install -e '.[service]'")`. `app.py` imports
FastAPI lazily inside `create_app()`.

D2 - **Dependency-light extras.** `service = ["fastapi>=0.115,<1",
"uvicorn>=0.34,<1", "httpx>=0.28,<1"]`. No `pydantic-settings` (a plain
dataclass reading `VLM_SERVICE_*` environment variables is consistent with
the codebase's dataclass style) and no `prometheus-client` (a minimal
counter/latency registry with Prometheus text exposition is ~100 lines and
keeps the extra small). Both choices can be revisited if requirements grow.

D3 - **Sync handlers on a threadpool.** Model calls are blocking. Route
handlers are plain `def`, so Starlette runs them in its threadpool; a
bounded `asyncio.Semaphore`/threading semaphore per capability
(`VLM_SERVICE_MAX_CONCURRENCY`, default 2) returns `503` when saturated.
No async model code in this iteration.

D4 - **Runtime wiring through `app.state`.** `service/runtime.py` builds
lazy singletons (generator, embedder, reranker, vector store) from env
vars plus an optional runtime YAML via `load_runtime_config`. Routers
receive them through `Depends`. Provider classes
(`QwenVLMProvider`, `QwenEmbeddingProvider`, `QwenRerankerProvider`,
`OpenAICompatible*Provider`) are reused instead of new adapters.

D5 - **Media and path policy (security).**

- `image` local paths must resolve inside `VLM_SERVICE_MEDIA_ROOT`
  (required when local paths are used); symlink escapes are rejected.
- Remote URLs are denied unless `VLM_SERVICE_ALLOW_REMOTE_IMAGES=1`; when
  enabled, scheme must be http(s) and response size is capped.
- `IndexRequest.output` is server-side; it must resolve inside
  `VLM_SERVICE_OUTPUT_ROOT`. Absolute paths and `..` traversal are
  rejected (`Path.resolve()` + `relative_to` check).

D6 - **Jobs are in-process only.** `service/jobs.py` keeps a bounded,
TTL-based registry (`accepted → running → completed/failed`), driven by
FastAPI background tasks. Single-process only; jobs are lost on restart
and documented as such. `ingest`, `index`, and `evaluate` are async by
default (`202` + `JobResponse`); `describe`, `embed`, `rerank`, and
`query` stay synchronous.

D7 - **Auth is optional but first-class.** When `VLM_SERVICE_API_KEY` is
set, requests must present `Authorization: Bearer <key>` or `X-API-Key`
(compared with `secrets.compare_digest`); otherwise `401`. `/health` and
`/metrics` are exempt by default (`VLM_SERVICE_PUBLIC_METRICS=0` to
protect metrics). No auth is enforced when the variable is unset, which
is the local-development default and must be stated in every doc example.

D8 - **Rate limiting is single-process.** Token bucket keyed by API key
or client IP, configured as `VLM_SERVICE_RATE_LIMIT=120/minute`, returning
`429` with `Retry-After`. Documented as not suitable behind multiple
workers/replicas.

D9 - **Error mapping.** `service/errors.py` registers exception handlers:

| Exception | HTTP | Notes |
|---|---|---|
| `RequestValidationError` | 422 | FastAPI default shape normalized to `ErrorResponse` |
| `InputValidationError`, `ValueError` | 400 | |
| `FileNotFoundError`, `PermissionError` | 400 | path errors are client errors |
| `OptionalDependencyError`, `ImportError` | 503 | keep the extra-install hint |
| `ModelLoadError` | 503 | |
| `VLMEngineeringError` | 400 | other package errors are treated as input/backend misuse |
| `RateLimitError` | 429 | with `Retry-After` |
| anything else | 500 | `request_id` only; no traceback in the response |

D10 - **Observability.** Middleware assigns a `request_id` (honoring an
incoming `X-Request-ID`), emits one JSON log line per request
(`method`, `path`, `status`, `duration_ms`, `request_id`), and
`service/metrics.py` maintains counters and latency summaries exposed at
`/metrics` in Prometheus text format.

## 9. Out of scope

- Multi-process/multi-node job durability, distributed rate limiting,
  shared metrics backends (single-process semantics documented instead).
- Streaming responses (SSE/WebSocket) — README roadmap keeps
  "async and streaming interfaces" separate; schemas define no streaming
  models today.
- OAuth/OIDC, TLS termination (reverse-proxy concern), multi-tenant
  quotas, GPU scheduling and autoscaling.
- Real-model/GPU certification (still opt-in via
  `VLM_RUN_REAL_MODEL_TESTS=1`).
- Video, grounding, quantization, and other README roadmap items not
  touched by the service layer.
- Any package-version change without explicit approval (see §7).

## 10. Decisions and open questions

Resolved:

1. Remote images stay **opt-in** (`VLM_SERVICE_ALLOW_REMOTE_IMAGES`),
   enforcing D5; remote URLs are rejected with 400 by default.
2. Per-request `model_size`/`model_id`/`model_path` overrides are
   **rejected with 400**. The service serves one configured model per
   capability; overrides would force reloads or be silently ignored.
3. `/v1/query` uses a **service-level default store** (`VLM_SERVICE_STORE`,
   default `memory`) plus `VLM_SERVICE_OUTPUT_ROOT`; the request schema
   stays unchanged. Added with the query route.
4. Use plain `uvicorn` (no `uvicorn[standard]`) in the extra; revisit if
   uvloop/httptools measurably help.
5. Keep the in-tree metrics registry; move to `prometheus-client` only
   when histogram requirements appear.
6. Jobs are process-local and bounded by `VLM_SERVICE_MAX_JOBS`
   (default 256) with a `VLM_SERVICE_JOB_TTL` retention window (default
   900s) for finished jobs. At capacity the oldest finished job is
   evicted; if every slot holds a running job the submission returns
   `503 service_busy` with `Retry-After`. Polling an unknown, expired or
   deleted id returns `404 not_found`; deleting an active job returns
   `409 job_conflict`. Job ids are UUID4 hex, so they are not guessable.
7. Async routes validate everything cheap before accepting a job: media
   roots for `ingest` (including directory expansion) and `evaluate`,
   the output root for `index`, chunk modality, and the requested store.
   A missing `[stores]` extra therefore answers `503` immediately
   instead of failing inside the background task. Model work and the
   embedding call itself run in the job, under a per-capability
   semaphore slot.
8. `index` and `evaluate` honour an explicit `embed_model_size` only when
   it equals the service preset (or `2b` when the service selects a
   model by id/path); `embed_model_path` is always rejected. Omitting the
   field uses the service-wide model.
9. Release number: **0.4.0**, confirmed by the maintainer on 2026-11-12.
   Metadata updates (`pyproject.toml`, version contract test, README,
   CHANGELOG) are part of Phase 6 release prep.
10. Authentication is opt-in through `VLM_SERVICE_API_KEY`. When set,
    every `/v1` route requires `Authorization: Bearer <key>` or
    `X-API-Key: <key>`; `/health` and `/ready` stay public, `/metrics`
    is public by default and protected when
    `VLM_SERVICE_PUBLIC_METRICS=false`. Keys compare in constant time
    as UTF-8 bytes.
11. Rate limiting is an in-process token bucket (`VLM_SERVICE_RATE_LIMIT`,
    default `120/minute`) keyed by the validated API-key fingerprint,
    else by peer IP. Rejections are `429 rate_limited` with
    `Retry-After`; probes are exempt; bucket memory is capped at 4096
    entries with oldest-first eviction.
12. `VLM_SERVICE_MAX_BODY_BYTES` (default 10 MiB) answers `413` for
    oversized or chunked bodies, `VLM_SERVICE_REQUEST_TIMEOUT` (default
    120s) answers `504 request_timeout` when a handler has not started a
    response, and every response carries `X-Request-ID` (caller-supplied
    safe ids are reused). Logs are one JSON line per request and metrics
    use the route template, never raw paths or headers.
