## 2. Findings

### F1 - TextChunker can exceed `max_chars` (High)

`src/vlm_engineering/documents/chunking.py:28-53`.

The hard-split fallback only runs when `current` is empty. When a normal
paragraph is followed by a large paragraph, the large paragraph (plus the
overlap prefix) is assigned to `current` verbatim and later flushed as an
oversized chunk.

Reproduction:

```python
from vlm_engineering.documents.chunking import TextChunker

TextChunker(max_chars=100, overlap_chars=0).split("A" * 50 + "\n\n" + "B" * 250)
# -> [50, 250]          <- 250 > max_chars
TextChunker(max_chars=100, overlap_chars=20).split("A" * 90 + "\n\n" + "B" * 95)
# -> [90, 117]          <- 117 > max_chars
```

Related defects in the same method:

- Paragraph splitting uses `text.split("\n\n")`, so CRLF input
  (`\r\n\r\n`) is not recognized as a paragraph boundary.
- When overlap is emitted, the new chunk is not re-checked against
  `max_chars`; overlap can also duplicate text beyond the intended window.
- No test covers an oversized paragraph that follows a non-empty chunk.

The class is public API (`vlm_engineering.TextChunker`) and its docstring
promises a "bounded character budget".

### F2 - Pillow security pin blocks all CVE fixes (High)

`pyproject.toml:57` pins `pillow>=12.3,<13`. Installed 12.3.0 has 39 known
vulnerabilities; `pip-audit` reports `13.0.0` as the fixed version. The
`Security` workflow and the `CI` workflow both run `pip_audit`, so these jobs
fail independently of code quality. Pillow 13.0.0 declares
`requires-python >=3.11`, which matches this project.

## 3. Remediation workstreams

### Phase 1 - Correctness (F1)

Rewrite `TextChunker.split` around a small invariant-driven algorithm:

1. Normalize newlines (`\r\n`, `\r` -> `\n`) before paragraph splitting.
2. Treat "emit a chunk" as one helper that trims and appends only non-empty
   chunks.
3. For every paragraph, if `len(current) + separator + len(paragraph)` fits,
   append it; otherwise flush `current` and start a new buffer from the
   overlap suffix plus the paragraph.
4. After adding overlap, if the buffer exceeds `max_chars`, hard-split the
   paragraph with `step = max_chars - overlap_chars` while guaranteeing
   progress.
5. Never emit a chunk longer than `max_chars`.

Tests to add (`tests/unit/test_documents_extended.py` or a new
`tests/test_chunking_budget.py`):

- oversized paragraph after a normal paragraph, with `overlap_chars=0` and
  `overlap_chars>0`;
- CRLF and mixed line endings;
- every chunk `<= max_chars` across randomized/fuzz inputs;
- no content loss (normalized concatenation covers every source character);
- overlap appears at the start of the following chunk;
- blank/whitespace-only input still returns `[]`;
- single paragraph shorter/longer than the budget.

Acceptance: the two reproductions in F1 return chunks whose maximum length is
`<= max_chars`, and the new property-style test passes.

### Phase 2 - Security and CI reachability (F2, F3, F4)

1. Bump `pillow>=12.3,<13` to `pillow>=13,<14`.
2. Re-run `pip-audit`; expected result: no known vulnerabilities.
3. Run the full suite on Pillow 13 to confirm image validation
   (`Image.open`, `verify`, `load`, `n_frames`, `DecompressionBombError`)
   still works.
4. Add `feature/**` (and optionally `docs/**`) to the CI push filters, or
   standardize branch naming to the existing `feat/**` convention.
5. `git rm --cached .github/workflows/.release.yml.swp`.

Acceptance: `pip-audit` clean, CI push filters cover the active branch,
swap file gone from the index.

### Phase 3 - Packaging and developer experience (F5, F6, F7)

1. Add `src/vlm_engineering/py.typed` (empty file) and configure it as
   package data so wheels and sdists include it.
2. Replace module-scope execution with:

   ```python
   if __name__ == "__main__":
       raise SystemExit(main())
   ```

   Add a subprocess test for `python -m vlm_engineering --help` and one error
   path (exit code 2).
3. Add a reproducible bootstrap path, for example a `make bootstrap` target
   or `scripts/dev-setup.sh` that creates a fresh `.venv`, upgrades
   pip/setuptools/wheel, and installs `-e ".[dev,config]"`. Document that a
   moved checkout requires recreating the venv.
4. Remove the ignored dead line in `cmd_rerank` or use the normalized output.

Acceptance: wheel contains `vlm_engineering/py.typed`; `python -m
vlm_engineering --help` exits 0; `make quality` works from a fresh venv.

### Phase 4 - CI hardening and polish (F8, F9, F10)

1. Add a build job that runs `python -m build`, `twine check dist/*`, and
   installs the built wheel into a clean venv before running the contract
   tests. This catches packaging regressions that editable installs hide.
2. Deduplicate the docs landing page: keep `docs/index.html` as the source
   and make `docs/interactive-architecture.html` a redirect, or delete the
   duplicate and update links.
3. Raise coverage focus rather than the global number: add targeted tests for
   `clip/encoder.py`, `text_embedding.py`, and the CLI error paths. Keep
   `fail_under = 80` unless the new tests justify raising it.
4. Optional: expose `__version__` via `importlib.metadata.version()` and use
   it in the version contract test instead of hardcoding `0.3.1`.
